When to use: a decision-maker needs a one-screen brief, not a thread.

Inputs: the topic after the command (`/brief release risk`).

Steps:
1. Pull from this channel (digest + search) and memory. Add web sources only if the topic needs current facts.
2. Structure: What / Why it matters / Options / Ask (the decision owed).
3. Keep it under one screen. Write `briefs/<slug>.md` if they will reuse it.

Output: the brief in chat (and a path if saved).

Approval: none to write. request_approval before emailing it out or posting to Slack via Composio.
