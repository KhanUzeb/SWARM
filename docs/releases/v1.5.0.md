# v1.5.0 release notes

Swarm `v1.5.0` is a self-hosted release of the local-first work increment
merged from `v0.1.0` (`dac7913`) through `origin/main`. It focuses on making
work state and approvals truthful, cancellations durable, agent tool calls
reliable, and the local SQLite backup/restore path honest.

**About the version number.** `1.5.0` is the release label the operator
selected for this increment. It does **not** assert that the five-gate
programme in `docs/product-upgrade/` is complete: Gates 2–5 remain open (see
[Known limitations](#known-limitations)). The authoritative record of what
shipped is the merged code and the commit hashes below.

## What changed

### Safety and durable work (Gate 1, partial)

- **Exact-bound, fail-closed approvals.** v2 workflow gates now use renewable
  leases with fencing generations, single-use grants consumed atomically with
  the unpark, a per-grant nonce in the binding hash, stale/expired state
  derivation, grant reissue and admin reconciliation, and fenced artifact
  writes. A generic workflow checkpoint is no longer treated as approval of a
  later, unspecified action (`68f82ce`, PR #45).
- **Truthful failures.** Workflows now fail on unreported work, missing
  configured agents, and agent errors instead of emitting success-shaped
  placeholders; conditional branch decisions persist across resume (`9c3e718`).
- **Stable work-event ordering.** Work events use one immutable, source-
  qualified global order so resume cursors stay stable when mixed chat/v2
  events are appended (`e46807f`). Clients with old *projected* cursors may
  receive a one-time replay when the mirror is populated.
- **Durable cancellation and single-source audit.** v2 run cancellation is
  committed in one fenced transaction and survives restart; work cancellation
  is fail-closed; a fenced executor stops on failed lease renewal; terminal
  settlement is atomic under concurrent work-list polls; and the run event
  stream is the sole audit record for mirrored work (`a5e7bbb`, `00c4097`,
  `18721d8`, PR #45).
- **Host execution stays opt-in.** `read_only_shell`, `computer_run` and plugin
  `shell` require explicit `SWARM_SYSTEM` opt-in and refuse the `none`/`fake`
  computer providers; approval labels say the execution is **not isolated**
  (`c25747b`). Host tools remain off by default.

### Agent reliability

- Malformed, non-object and non-string tool arguments are rejected instead of
  being fed back into the loop; loop/stall guards are enforced; streamed
  cutoffs are narrated honestly; file writes are verified (including exact
  Windows newline handling); an empty reply is a real failure; and read
  truncation reports explicit evidence (`767a7c7`, `ed30034`, PR #44).
- Budget-trimmed memory is applied to the actual agent prompt (`01bf1a9`).
- Token-budget enforcement is honest when provider usage is missing: unknown
  or malformed fields are not counted as zero, known fields still stop the run
  at the cap, and no extra closing call is made on exhaustion (`957aa1b`).
  A call can still overshoot the limit; savings are not measured.

### Local install and data

- Online SQLite backup uses a per-target `O_EXCL` lock and crash-safe
  preserve-before-publish staging; restore is fail-closed and documented as
  requiring a **stopped instance** (`9fcec19`, `451206f`). CLI `backup` and
  `restore` run locally without a server or token.
- `swarm doctor` is self-contained under the default Windows console encoding
  and the model-catalog test is environment-hermetic (`7559ccc`).
- Windows onboarding explains `SWARM_SECRET` before connecting a provider.

### Work UX

- The work rail names the real approval gate, work status is truthful before
  an executor claims it, and work outcomes, authenticated artifact downloads
  and live status are surfaced (`0cf5745`, `696ef90`, PR #42). The station-board
  visual contract in `AGENTS.md` §8a is preserved.

### Documentation

Gate 0 baseline, phase log, release-readiness assessment, closeout notes and
future-scope record were added under `docs/product-upgrade/`.

## Docker image

Multi-arch image (`linux/amd64`, `linux/arm64`) published to GHCR:

```bash
docker pull ghcr.io/khanuzeb/swarm:v1.5.0
docker pull ghcr.io/khanuzeb/swarm:latest   # tracks the newest v* tag
```

Use `docker compose up -d` with the pinned image in `docker-compose.yml`.
See [docs/DEPLOY.md](../DEPLOY.md) for environment variables and host tools.

## Verification

- GitHub Actions `ci.yml` on the merged commit runs the backend suite
  (`python -m pytest -q`), frontend contract tests (`bun test`), a production
  build (`bun run build`) and the JS bundle budget. That CI result — not a
  local claim — is the release gate.
- Local checks in this release branch avoided `pytest` per the standing
  operator instruction: `bun install --frozen-lockfile` and `bun run build`
  (1930 modules; every JS chunk within the CI raw/gzip budget) and
  `py_compile` on the changed Python file. The local Docker CLI had no
  running daemon, so the image build is verified by the GitHub workflow
  instead. `doctor` was not run locally because this interpreter lacks the
  project dependencies; CI installs them.
- Earlier, pre-release evidence recorded focused backend test runs and 99
  frontend tests; those are **not** a substitute for the CI run on the
  released commit.

## Known limitations

- Gates 2–5 of the product-upgrade programme are not complete: no guided
  first-run wizard, no consolidated Desk/Work cockpit, no reproducible
  evaluation harness or measured cost/retrieval results, and no MCP client or
  curated integration.
- **The sandbox is a working directory plus a timeout — not container or
  network isolation.** Host tools are off unless `SWARM_SYSTEM=1`.
- No browser end-to-end acceptance run, no live-provider cost measurement, and
  no true multi-process kill-and-recover test. Exactly-once *effects* are not
  claimed without an external idempotency contract.
- Restore is verified only against a stopped instance; no live-volume upgrade
  smoke test is claimed.
- Knowledge search is keyword-only (FTS5 + LIKE), no vector/semantic search.
  Provider credentials are workspace-global, not per-user. There is no token
  revocation and usage cost is collected but not surfaced as a dollar figure.
- Python dependencies use lower-bound floors rather than a canonical lockfile.

## Upgrade note

SQLite upgrades are additive (`ensure_schema()` + versioned migrations). Back
up the database before upgrading, as documented in `docs/DEPLOY.md`; restore
requires a stopped instance.
